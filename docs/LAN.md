# Дуэль Linux ↔ Windows 11 в одной сети

Обоим нужна одна версия игры: 360 тиков логики/с, пакет каждые 6 тиков (60 Гц).
Разные протоколы/частоты не соединятся. Рендер зависит от vsync монитора.

Если у вас уже есть Windows ZIP, распакуйте его и переходите к запуску ниже.
Для готового `.exe` Rust и Build Tools на ноутбуке не нужны.

## Игра вдвоём

1. Подключите оба компьютера к одной LAN/Wi-Fi без изоляции клиентов/гостевой сети.
   Распакуйте Windows ZIP в отдельную папку. Запускайте из папки с `examples/`.
2. Linux:

   ```sh
   target/release/ssk online --config examples/lan.yaml --class cadet
   ```

3. Скопируйте полную строку `SSK invite: ssk1:…` из терминала или нажмите **F2**
   в игре. Передайте приглашение на ноутбук любым удобным способом.
4. На Windows в PowerShell, из распакованной папки:

   ```powershell
   .\ssk.exe online --config .\examples\lan.yaml --class spark --connect 'ssk1:ВСТАВЬТЕ_ПРИГЛАШЕНИЕ'
   ```

5. Если Windows спросит разрешение сети для `ssk.exe`, разрешите **частную сеть**.
   На обоих компьютерах входящий UDP 4200 должен быть разрешён в LAN.
   UDP 4201 нужен для discovery, прямой дуэли по приглашению он не обязателен.
   Проброс портов на домашнем роутере для одной LAN не нужен.
6. В HUD должен появиться `1 peers`, соперник или указатель его направления,
   значения RTT/TX/RX. Затем WASD, мышь, ЛКМ/Space, 1–3/Q/E, Shift/ПКМ.
   Смерть → респаун через 2 секунды; Esc выбирает корабль следующего респауна.
   Онлайн-меню не останавливает бой.

`runtime/identity.key` создаётся отдельно на каждом компьютере. Не переносите
его вместе с игрой: один ключ означает одного игрока. Конфиг LAN использует
порт 4200; два процесса на одной машине запускайте с `examples/player-a.yaml`
и `player-b.yaml` из репозитория.

Если связи нет: проверьте полное приглашение, одну версию игры, firewall,
IP-адрес нужного адаптера и отсутствие client isolation. При необходимости
задайте `advertise: 192.168.x.x:4200` в конфиге соответствующего компьютера.
Приглашение после этого нужно получить заново. Самостоятельный relay нужен
при отсутствии прямой связи между сетями; настройка описана в README проекта.

Это инструкция запуска. Ручной матч Linux↔Windows 11 ещё не проведён.

## Сборка из исходников (из корня репозитория)

Linux, из корня репозитория:

```sh
cargo build --locked --release -p ssk --jobs 2
```

Windows x64: установите Rust через [rustup](https://rust-lang.org/learn/get-started/)
и Visual Studio Build Tools с **Desktop development with C++** и Windows SDK.
[Официальная инструкция Microsoft](https://learn.microsoft.com/en-us/windows/dev-environment/rust/setup).
Откройте Developer PowerShell / x64 Native Tools, перейдите в репозиторий:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-windows.ps1
```

Результат: `dist/ssk-windows-msvc.zip`. Скрипт собирает, тесты не запускает.
Собирать на Windows через MSVC удобно для дальнейшей разработки на ноутбуке.
Кросс-сборка на Linux тоже поддержана: `tools/build-windows.sh` использует
`x86_64-pc-windows-gnu` и MinGW-w64, создаёт `dist/ssk-windows-gnu.zip`.
Можно просто скопировать готовый ZIP на ноутбук и распаковать его.
Ни Rust, ни Build Tools на ноутбуке для готового `.exe` не нужны.


Текущие release-сборки Linux x64 и Windows x64 GNU получены на Linux.
