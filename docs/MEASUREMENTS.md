# Исторические замеры: 240 Гц / сеть 30 Гц

Дата: 2026-10-19, release `22a9737`, Ubuntu 26.04.1 x86_64,
Intel i9-10980XE 3 ГГц, 36 логических CPU, 126 ГиБ RAM.
**После перехода на 360/60 эти цифры не оценивают текущую ёмкость.**

Настоящий QUIC loopback; подписанный заранее известный состав; движение,
стрельба, способности, респаун и общие объекты. 8 потоков симуляций,
отдельные сетевые runtime. Без GPU и времени схождения DHT. Метрики BPS/PPS
считают игровой payload без QUIC/DHT/NAT overhead. Это короткие замеры.

На64: степень21; p95 TX547260 Б/с; p95 PPS/связь30,02;
p95 критической очереди6. Общий снимок присутствовал во всех срезах.
Общие счётчики включают startup: например, максимум1815 истёкших событий
у64 за весь запуск, несмотря на нулевой прирост после первого среза замера.
На128 медиана доли реплик моложе250 мс —0,181; медиана количества общих
снимков —0. Стенд перегружен, режим не принят.

## Принудительный relay

[Два Docker bridge](../tools/nat/README.md); UDP кроме DNS запрещён внутри
контейнеров; собственный HTTP relay, TCP/WebSocket. Оба клиента получали
снимки соперника через relay; p95 возраста32,4/34,0 мс, measured expiry/drop0.
Первый клиент работал45 с, второй40 с; поэтому последние срезы первого
включают отсутствие уже вышедшего соперника. Оба отчёта были прочитаны;
временный Docker stack удалён. Публичный интернет, TLS-деплой, все типы NAT
и failover публичных relay не проверялись.

Числа перенесены из прочитанных отчётов `/tmp/ssk-final-*.json` и
`/tmp/ssk-nat-{a,b}.json`. После сообщения о зависании ОС исходные временные
JSON оказались недоступны; они не включены в репозиторий. Никаких утверждений
о новых360 Гц на основании этих результатов не делаем.
